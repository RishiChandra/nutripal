Photo → Macro Estimation Subagent

Input: one or more meal photos. Output: a structured report of ingredients, portions, macros, and confidence — plus user clarification prompts when confidence is low.

Why it's shaped this way

  • Identification and portion are separated because they fail for different reasons and carry independent confidences. Portion is the one to obsess over.
  • Macros come from the DB, not the model. Stage 4 looks up canonical values by (item, grams) so numbers are consistent and auditable — the VLM never free-hands "43g protein."
  • Uncertainty flows forward. Total confidence is dominated by portion confidence; a shaky gram estimate should visibly widen the meal's error band.
  • The gate feeds your voice loop. Low confidence becomes a spoken question; the answer re-enters at Stage 3 and doubles as labeled data for later fine-tuning.

Confidence & gating

  • Per-item confidence = f(recognition_conf, portion_conf, db_match_conf), with portion_conf weighted heaviest.
  • Gate triggers if any high-impact item (large share of total calories) or the meal total falls below threshold — not just any low number.
  • Prompts are targeted: ask only about the item driving the uncertainty, phrased for a one-breath voice answer.
  • Report always ships a best estimate even when unprompted — the prompts refine, they don't block.

Report contract (sketch)

{
  "ingredients": [
    { "name": "white rice", "portion_g": 210, "portion_desc": "~1.5 cups",
      "macros": { "kcal": 274, "protein_g": 5.3, "carb_g": 59, "fat_g": 0.6 },
      "micros": { "fiber_g": 0.9 },
      "confidence": { "recognition": 0.94, "portion": 0.55, "db_match": 0.9, "overall": 0.6 } }
  ],
  "totals": {
    "macros": { "kcal": 612, "protein_g": 41, "carb_g": 63, "fat_g": 19 },
    "micros": { "fiber_g": 4.2, "sodium_mg": 780 },     // best-effort
    "confidence": 0.63,
    "kcal_range": [520, 705]                             // portion-driven band
  },
  "clarification_prompts": [
    { "item": "white rice", "reason": "portion", "ask": "Was the rice about a cup, or closer to two?" }
  ],
  "meta": { "photos": 2, "depth_used": false, "reference_object": null }
}

Macros are required on every item and on totals; micros are populated when the DB entry has them, omitted otherwise. The compiler agent consumes totals and surfaces clarification_prompts to the orchestrator.
